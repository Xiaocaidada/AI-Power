## Commands

All Python commands use the project venv. On Windows that is `.venv/Scripts/python.exe`.

- Setup: `uv venv --python 3.13 .venv && uv pip install --python .venv/Scripts/python.exe -e ".[dev]"`
- Run tests: `.venv/Scripts/python.exe -m pytest`
- Run one test: `.venv/Scripts/python.exe -m pytest tests/test_documents.py::test_upload_ingests_and_marks_ready`
- Coverage: `.venv/Scripts/python.exe -m pytest --cov=app --cov-report=term-missing`
- Lint: `.venv/Scripts/python.exe -m ruff check .`
- Format: `.venv/Scripts/python.exe -m ruff format .`
- Run app: `.venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8000`
- Migrations: `.venv/Scripts/python.exe -m alembic upgrade head` (new revision: `... revision --autogenerate -m "..."`; requires a DB whose schema matches the models)
- Docker API + worker: `docker compose up -d api worker` (API runs `alembic upgrade head` before uvicorn; host port **8002**, because the VM's 8000/8001 are occupied by vLLM)
- Docker full stack: `docker compose up -d --build` (adds `web` on **8080** and `backup`; web serves the built SPA and proxies `/api` to `api:8000`)
- Logs: `docker compose logs -f api worker web`
- Metrics: `curl http://192.168.29.100:8002/metrics` (Prometheus text; LAN only)
- Optional Prometheus: `docker compose --profile observability up -d prometheus` (UI on **9090**)
- Optional HTTPS: set `CADDY_DOMAIN` in `.env`, then `docker compose --profile https up -d caddy` (ports 80/443; Caddyfile in `deploy/`)
- Manual backup now: `docker compose exec -e RUN_ONCE=1 backup /bin/sh /usr/local/bin/backup_postgres.sh`
- Load test: `.venv/Scripts/python.exe scripts/loadtest.py --base-url http://192.168.29.100:8080/api --concurrency 20`
- Workflow example: `AI_POWER_BASE_URL=... AI_POWER_EMAIL=... AI_POWER_PASSWORD=... .venv/Scripts/python.exe scripts/workflow_example.py --provider local-qwen --model <model>`
- Workflow load test: `.venv/Scripts/python.exe scripts/loadtest_workflow.py --base-url http://192.168.29.100:8002 --provider local-qwen --model <model> --concurrency 3`
- Docker build uses the Tsinghua PyPI mirror by default; override with `docker compose build --build-arg PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ api`
- Async run events (JWT): `curl -N "http://192.168.29.100:8002/workflows/runs/<run_id>/events?after=0" -H "Authorization: Bearer $TOKEN"`
- Cancel a run: `curl -X POST "http://192.168.29.100:8002/workflows/runs/<run_id>/cancel" -H "Authorization: Bearer $TOKEN"`
- Provider configs: `curl -s http://192.168.29.100:8002/provider-configs -H "Authorization: Bearer $TOKEN"`
- Public marketplace: `curl -s http://192.168.29.100:8002/market/models`
- Seed public marketplace: `docker compose cp scripts/seed_market_models.py api:/tmp/seed_market_models.py && docker compose exec -T api python /tmp/seed_market_models.py`

## Architecture

- **Layering**: `app/routers/*` (HTTP) → `app/deps.py` (auth + provider registry) → `app/services/*` (access, parsing, chunking, storage, ingestion, retrieval, rag, evaluation) → `app/models.py` / `app/schemas.py` / `app/security.py`. `app/providers/` owns LLM + embedding boundaries; `app/vector.py` owns the pgvector/JSON type.
- **Auth flow**: argon2id hashing; `POST /auth/login` returns a 30-minute HS256 access JWT (`sub` = user UUID, plus `jti`) and a 7-day refresh token. `POST /auth/refresh` rotates the refresh token once (old one is revoked and reused tokens are rejected); `POST /auth/logout` revokes it. Refresh tokens are stored as SHA-256 hashes in `refresh_tokens`. Login is rate limited per client IP via Redis (10/min, fail-open with a warning). Every protected route resolves `User` via `HTTPBearer`; cross-user resource access returns **404, not 403**.
- **Traces**: each chat message writes a `traces` row keyed by `request_id` (also stored on `messages.request_id`) with `retrieval_ms`, `ttft_ms`, `total_ms`, status/error code and routing attempts. `GET /traces/{request_id}` is workspace-scoped; the worker deletes traces older than 7 days at 03:15.
- **Quotas**: static `free`/`pro` limits in settings (requests/min, tokens/day, max keys). Redis counters guard message sends and uploads; 429 responses carry `quota_exceeded` plus `Retry-After` and `X-Quota-*` headers. Tokens accrue after a stream finalizes (NULL usage = 0). API keys may have `expires_at` and `rate_limit_per_minute`; expired keys return 401. Redis failures fail open.
- **Costs / usage ledger**: every billable LLM call writes one append-only `usage_events` row — chat finalize, workflow `llm`/`agent` nodes, and collaboration planner/worker/critic steps. Rows carry `source` (`chat|workflow|collaboration`), `api_key_id`, unique nullable `workflow_node_run_id`/`collaboration_step_id`, and a nullable `message_id`; the migration backfills history as `source='chat'`. `app/services/usage_ledger.py` snapshots `input_price`/`output_price` from `model_catalog` at write time and stores `cost = prompt/1e6*input + completion/1e6*output` (6 decimals), so later catalog changes never rewrite history. `GET /usage/cost` groups by day/provider/model/source with optional `source`/`api_key_id` filters; `GET /usage/by-key` attributes requests/tokens/cost per key (JWT calls form an unattributed bucket). Budgets sum all sources.
- **Model marketplace**: `market_models` stores public display metadata (category, capabilities, I/O types, context, featured/new, sort, docs) separately from `model_catalog` routing/pricing. `GET /market/models` and `/market/models/{slug}` are unauthenticated and filter by search/category/capability/provider/input/output; admin CRUD lives under `/admin/market/models` (non-admin 404). `scripts/seed_market_models.py` seeds from platform provider model lists. The frontend uses two sources: public market and `/provider-configs/models` for “My models”; it keeps the platform `/models` comparison tab. Model experience deep-links to `/chat/new?provider=&model=`. User provider models are capability-validated on conversation creation (`chat`, or `tools` for agents).
- **Provider Hub**: `provider_configs` are workspace-scoped and owner-private by default, with optional read-only sharing to workspace members. API keys are Fernet-encrypted with `PROVIDER_SECRET_KEY` (dev falls back to JWT), stored with a masked hint, and never returned by the API. Users can test/sync OpenAI-compatible endpoints, manually add models, and tag capabilities. `get_scoped_registry` merges platform providers with the caller's private/shared configs for chat and agents; workflow/collaboration workers build the same registry from the run owner. Provider config management is JWT-only; cross-workspace/private access is 404.
- **Tenancy**: every user gets a personal `workspace` at registration. Resources (`knowledge_bases`, `conversations`, `documents`, `chunks`, `ingestion_jobs`, `usage_events`, `api_keys`) carry `workspace_id`; `AuthContext` = user + workspace + role + scopes. JWT requests pick a workspace via `X-Workspace-Id` (defaults to personal); API keys are bound to their workspace and reject a conflicting header. Cross-workspace access returns 404. Owners invite/remove members by email; members see workspace resources.
- **Admin/audit**: `users.role == "admin"` gates `/admin/*`; non-admins get 404 (anonymous 401). Admin endpoints list users, workspaces/members, global usage/cost, and all catalog models, and toggle `model_catalog.enabled`. Toggles write `audit_logs` (`model.toggle`); the worker deletes audit rows older than `AUDIT_LOG_RETENTION_DAYS` at 03:30. A seeded catalog is authoritative: if all rows are disabled, `/models` stays empty instead of falling back to live provider models. Admins can change a workspace plan (audited `workspace.plan_change`, effective immediately), and `/admin/runs/summary` reports workflow/collaboration failure rates; workflow creation/version publish writes `workflow.publish` audits. Grant admin with `python scripts/grant_admin.py <email>`.
- **Workflows**: `workflows` + immutable `workflow_versions` store `{nodes, edges}` definitions. Node types are `llm`, `kb_search`, `tool`, `agent`, `condition`, `parallel`, `join`; validation enforces unique ids, whitelisted configs, one entry, reachability, acyclicity, condition true/false edges, parallel fan-out, and join fan-in. The event-driven executor skips unselected condition branches, propagates skips, waits for all active predecessors at joins, and bounds parallel branches with `WORKFLOW_PARALLEL_LIMIT`. `POST /workflows/{id}/runs` validates and enqueues a `queued` run (`202 + run_id`); `run_workflow_job` claims it atomically and consumes the runner in the worker. `workflow_run_events` stores `workflow_start/node_start/node_end/workflow_end` with monotonic `seq`; `GET /workflows/runs/{id}/events?after` replays and tails (300ms), supports `Last-Event-ID`, and closes at terminal status. `POST /workflows/runs/{id}/cancel` cancels queued runs immediately or sets `cancel_requested_at` for running runs, checked at node boundaries. `workflow_runs`/`workflow_node_runs` persist status, attempts, durations, truncated summaries, `kb_id`, `api_key_id`, and cancellation state. Nodes render `{{input}}`/`{{node_id}}`, retry ProviderErrors up to `WORKFLOW_NODE_ATTEMPTS`, check quota per LLM node, and reuse provider metering, tools, and the P3 agent runner; each successful `llm`/`agent` node writes one `usage_events` row (`source='workflow'`), while the run aggregates the same costs.
- **Collaboration**: `POST /collaborations/runs` enqueues a `queued` run (`202 + run_id`); `run_collaboration_job` executes planner → parallel workers → critic and writes `collaboration_run_events` for replay/tail. `POST /collaborations/runs/{id}/cancel` applies the same queued/running cancellation semantics at step boundaries. The planner must return JSON with 2–`COLLABORATION_MAX_TASKS` tasks (`retrieval|math|general`); workers reuse `AgentRunner` with a root agent and run under `COLLABORATION_PARALLEL_LIMIT`. The critic returns `accept` (with `final_answer`) or `revise` (feedback); revisions rerun workers, capped by `COLLABORATION_MAX_ROUNDS`. A global `COLLABORATION_MAX_STEPS` budget and per-step quota checks bound cost; `collaboration_runs`/`collaboration_steps` persist plan, rounds, outputs, tokens, and cost, and each planner/worker/critic step writes one `usage_events` row (`source='collaboration'`, including failed workers that consumed usage).
- **Prompt templates**: `prompt_templates` + immutable `prompt_versions` are workspace-scoped; `{{variable}}` names are extracted per version. Creating a conversation with `prompt_version_id` renders the prompt server-side into `conversations.system_prompt` (snapshot) and stores the version id, so later edits/deletes do not change history. Non-agent chats use the snapshot as the system prompt (combined with RAG references when a KB is attached); agent chats use it as the supervisor prompt. Templates are soft-deleted; cross-workspace access is 404.
- **Agents/tools**: `conversations.agent=true` runs a supervisor that delegates through the built-in `delegate_to_agent` tool to `retrieval` and `math` sub-agents. Tools live in `app/tools/` (Pydantic args, timeout, output truncation), agents in `app/agents/`, and the loop in `app/services/agent.py` parses one JSON object per model turn (`tool` or `final`), caps total steps at 8 and depth at 2, checks quota per LLM call, and aggregates all step tokens into one message. `retrieval` has `kb_search` (workspace + conversation-KB scoped; collected chunks become `citation` SSE events and persisted citations) and `current_time`; `math` has the AST-whitelisted `calculator`. SSE adds `agent_start`/`agent_end`/`tool_call`/`tool_result`; `traces.agents` stores metadata only (no tool arguments or output text). Unparseable output is treated as the final answer.
- **API keys**: `X-API-Key` (format `ap_<8hex>_<secret>`) is accepted by `get_auth_context`; only SHA-256 hashes are stored in `api_keys`, plaintext is returned once at creation. JWT = full permissions; keys are limited by `chat:write` / `kb:read` / `workflow:run` via `require_scope`. Key management, provider-config management, uploads, deletes, archive, webhooks, and `/usage` stay JWT-only. `last_used_at` is written at most once per 60s. Never log key values.
- **Frontend contract**: `CORSMiddleware` allows origins from `CORS_ORIGINS` (default Vite `5173` + LAN `8080`), permits `Authorization`/`Content-Type`/`X-API-Key`, and exposes `Retry-After`. `GET /knowledge-bases/{kb_id}/documents` lists non-deleted documents newest-first (UUIDv7 tiebreak) behind `kb:read`; cross-user returns 404.
- **Portal**: `PortalLayout` serves unauthenticated `/`, `/models`, `/models/:slug`, `/announcements`, `/announcements/:id` and wraps the auth-gated `/models/:slug/playground` with the public top nav. The home page consumes `/home` for banners/featured/activity placements and recent announcements, plus `/market/models` for featured/new cards; the model detail page renders descriptions/specs plus platform API, Python SDK and OpenAI-compatible examples; the playground reuses the chat composer/message components, creates a conversation on first send, and keeps `?conversation=` for refresh. Authenticated users get a notification bell with unread count and mark-all. Login/RequireAuth preserve return paths.
- **Home content**: `home_placements` rows are kind=banner/featured/activity with `sort_order`, `enabled`, and an optional `starts_at`/`ends_at` window; `announcements` are platform-wide with `status` (draft/published/archived), `pinned`, `published_at`, and `expires_at`; `announcement_reads` stores one row per `(announcement_id, user_id)`. Public `/home`, `/announcements`, `/announcements/{id}` expose only active published content (404 otherwise). `/notifications` is JWT-only, returns `unread_count` plus `read_at` per item, and `read-all` marks only the caller's unread visible announcements. Admin `/admin/content/placements|announcements` CRUD is admin-only (404 otherwise), writes `audit_logs`, validates schedule windows, and only accepts site-relative or http(s) URLs for image/cover/link fields.
- **Frontend (`web/`): Vite + React 18 + TypeScript, React Router, TanStack Query (server state), Zustand (auth/UI only), Tailwind tokens. `/api` is proxied in dev. Access token lives in memory; refresh token in `localStorage` with single-flight rotation and one retry on 401. Chat uses `fetch` + `ReadableStream` (not EventSource), parses `meta/citation/delta/usage/done/error`, renders plain text while streaming and Markdown after `done`, and replays persisted citations on history load. zh/en dictionaries are typed and key-parity tested. A sidebar button toggles light/dark: `html.dark` swaps CSS variables, the choice is stored in `localStorage.ai_power_theme`, and the first visit follows `prefers-color-scheme`. Routes: `/login`, public `/`, `/models`, `/models/:slug`, `/models/:slug/playground`, `/announcements`, `/announcements/:id`, console `/chat`, `/chat/:id`, `/knowledge`, `/knowledge/:id`, `/workflows`, `/collaborations`, `/evaluation`, `/usage`, `/settings/providers`, `/settings/api-keys`, `/settings/workspace`, `/settings/prompts`, `/settings/profile`, `/admin` and `/admin/content` (admins only). A workspace switcher in the sidebar drives `X-Workspace-Id`; message details open a trace drawer; usage shows quota windows, source grouping, and per-API-key reconciliation; workflow/collaboration pages submit runs, show run history, reconnect from `?run=<id>` after refresh, and expose cancel. Usage loads Recharts lazily. Uploads use XHR for progress; multi-select/drag-drop files are queued sequentially with per-file status (`uploading/ready/duplicate/failed`), and document status polling runs every 2s only while a document is `uploaded/parsing/embedding`. The console sidebar is grouped into Work (chat, knowledge), Build (workflows, collaborations, evaluation) and Account (usage, settings, admin); provider/API-key/prompt/webhook/workspace/profile pages live under the card-based `/settings` hub. API keys are shown in full once (non-dismissible dialog) and never persisted client-side. Chat exports download Markdown/JSON via an authenticated blob request.
- **Model catalog & routing**: `model_catalog` holds provider/model metadata (`priority`, `enabled`, prices, tags). `GET /models` merges it with circuit health; `GET /models/compare?ids=` compares up to 5. Conversations can use `provider_id="auto"`, which resolves candidates by priority, skips providers with ≥3 Redis failures in 60s, and falls back to the next provider only before the first token. Mid-stream failures emit an SSE `error` and are not retried. Messages store the actual provider/model used.
- **Provider boundary**: `LLMProvider` (`list_models`, `stream_chat`) + `EmbeddingProvider` (`embed`). `OpenAICompatProvider` / `OpenAICompatEmbeddingProvider` implement DeepSeek / llama.cpp / vLLM. Streaming chat sends `stream_options.include_usage=true`; usage stays nullable.
- **Chat flow**: `POST /conversations/{id}/messages` persists user + assistant (`streaming`) messages, then streams SSE `meta → delta* → usage → done` (or terminal `error`). When the conversation has `kb_id`, retrieval runs **before** messages are persisted and the stream becomes `meta → citation* → delta* → usage → done`; a retrieval provider failure returns HTTP 502 `retrieval_failed` and persists nothing. The generator finalizes the assistant message in a fresh `SessionLocal` session and writes one append-only `usage_events` row (even when usage is null) plus any `message_citations`. `GET /conversations/{id}` replays persisted citations.
- **KB model selection**: KB settings include `embedding` and `rerank` selections (`provider_config_id`, `model`, dimensions). Ingestion and retrieval resolve the KB’s own/shared provider config, decrypt its key, and build OpenAI-compatible embedding / rerank clients; unavailable configs fail ingestion or disable rerank. Platform defaults apply when no provider is selected.
- **Conversation export**: `GET /conversations/{id}/export?format=markdown|json` reuses the conversation-detail loader, includes messages and persisted citations, and returns an attachment (`conversation-<id>.md|json`). JWT or `kb:read` API keys are accepted; cross-workspace is 404.
- **Usage API**: `GET /usage/summary?from&to&group_by=day|provider|model|source` and `GET /usage/cost` are workspace-scoped SQL aggregations with optional `source`/`api_key_id` filters; `GET /usage/by-key` returns per-key requests/tokens/cost plus an unattributed bucket for JWT calls. Chat events keep `message_id`/`conversation_id`; run events use node/step ids and `message_id=NULL`.
- **Ingestion flow**: `POST /knowledge-bases/{kb_id}/documents` validates ownership + extension, writes a UUID-named file under `UPLOAD_DIR`, inserts `Document(uploaded)` + `IngestionJob(queued)`, and enqueues `ingest_document_job` on Arq (job id `ingest:<document_id>`). The worker runs `uploaded → parsing → embedding → ready`; failures return an `IngestionOutcome`, retry with `2**attempts` backoff (max `INGESTION_MAX_ATTEMPTS`), then mark the job `dead`. Each run sets `started_at`/`lease_expires_at`; a per-minute cron requeues `running` jobs with expired leases. `POST /documents/{id}/retry` resets a failed document and enqueues it again. Queue failure marks the document `failed + queue_unavailable` and returns 503. Duplicate `(user, kb, content_hash)` returns the existing document with `duplicate=true`.
- **Retrieval/RAG flow**: `retrieve_chunks` embeds the query once, loads the KB's `settings` (falling back to global `RETRIEVAL_*`), filters `chunk.workspace_id`, `chunk.kb_id`, `document.status='ready'`, `document.deleted_at IS NULL`, and runs vector recall (pgvector L2 / SQLite Python fallback). With hybrid enabled it also runs Postgres `pg_trgm` lexical recall (`similarity` / `word_similarity` / substring) or a SQLite character-bigram fallback, fuses both with RRF (`1/(60+rank)`), then optionally reranks up to `RERANK_MAX_CANDIDATES` (8) truncated chunks via `POST {RERANK_BASE_URL}/rerank` (`bge-reranker-v2-m3`); rerank failures fall back to fused order and increment a metric. `fit_context` greedily keeps ranked chunks within `RETRIEVAL_MAX_CONTEXT_CHARS`; citations are built **from the chunks actually placed in the prompt** (never parsed from model text); `build_rag_messages` prepends a system prompt that declares `<reference_material>` untrusted data. KB settings are workspace-scoped; chunking changes only apply to new ingestion or `POST /documents/{id}/reprocess`. Product endpoints: `GET/PATCH /knowledge-bases/{id}/settings`, `GET /knowledge-bases/{id}/chunks|stats`, `POST /knowledge-bases/{id}/retrieval/search` (JWT-only; vector/lexical/fused/rerank ranks + timings), and a `/knowledge/:id` UI with Documents/Chunks/Retrieval/Settings tabs.
- **Evaluation platform**: `eval_datasets`/`eval_questions`/`eval_runs`/`eval_run_items` are workspace-scoped. `POST /evaluations/runs` snapshots retrieval options and enqueues `run_evaluation_job` (Arq); the worker reuses `retrieve_chunks`, computes doc-level Recall@1/3/5, MRR, optional evidence hit rate, and P50/P95 latency per question, updating `progress_done`. Datasets can import the raw `eval/dataset.json` bundle (`/evaluations/datasets/import`), mapping filenames to ready documents in the selected KB. Optional answer generation + LLM-as-judge reuses `build_rag_messages`; the judge must return `{score:1-5, faithful:bool, reason}` JSON, and judge failures are stored per item without failing the run. `/evaluation` lists datasets/runs, starts runs, shows metrics/failed questions/answers, and compares two runs.
- **SDK**: `sdk/python` (`ai_power_sdk`) is an installable sync/async httpx client. It supports login/refresh/API-key modes, typed error mapping (`AIPowerError`), GET retries on 429/5xx, and SSE parsing (`SSEEvent`); capabilities cover chat, KB upload/wait, retrieval search, workflow/collaboration runs, models, and usage. It is not published to PyPI; `workflow_run`/`collaboration_run` submit a queued run then stream its events, and `start_*`, `*_run_events`, and `cancel_*` support reconnect/cancel.
- **Webhooks**: workspace-owner-only `webhooks` subscriptions with encrypted `whsec_` secrets (Fernet key derived from `WEBHOOK_SECRET_KEY`, dev fallback JWT secret). `enqueue_event` writes `webhook_deliveries` from business code without network I/O; the worker scans due deliveries every minute, validates URL/DNS (SSRF guard, optional private hosts), signs `t=<unix>,v1=HMAC_SHA256(secret, f"{t}.{body}")`, and retries 1m/5m/30m/2h/6h up to `WEBHOOK_MAX_ATTEMPTS`. Events: `message.completed`, `document.ready`, `document.failed`, `workflow.completed`, `collaboration.completed`, `budget.exceeded`. `/settings/webhooks` shows subscriptions and delivery logs with replay.
- **Vector storage**: `EmbeddingVector` maps to pgvector `vector(1024)` on Postgres and JSON on SQLite. `init_db()` creates the `vector` extension and the idempotent HNSW index (`ix_chunk_embeddings_embedding_hnsw`, `vector_l2_ops`) on Postgres. Distance queries use `EmbeddingVector` comparators (`l2_distance`, `cosine_distance`).
- **Persistence**: dev/tests use SQLite (`aiosqlite`, `NullPool`); production targets Postgres + pgvector via `DATABASE_URL`. Schema changes go through Alembic (`alembic/versions/`); `init_db()` still creates tables for tests and local dev. The Docker API command runs `alembic upgrade head` before uvicorn.
- **Deployment**: compose runs `postgres`, `redis`, `api`, `worker`, `web`, `backup`. nginx serves `web/dist`, falls back to `index.html`, and proxies `/api/` to `api:8000` with proxy buffering off for SSE; host ports are 8080 (web) and 8002 (api). `backup` runs `pg_dump -Fc` daily into the `backups` volume and keeps 7 days. API/worker use `LOG_FORMAT=json`; every request carries `X-Request-ID` and logs `method/path/status/duration_ms/user_id`. Streaming endpoints close their request-scoped DB session before returning, and the Postgres pool is 10+20 with `PROVIDER_TIMEOUT_SECONDS=180` in compose to survive 20 concurrent local-model streams.
- **Metrics/budget**: `/metrics` renders Prometheus text from a process-local registry: HTTP request counts/latency by route template, active SSE streams, tokens/cost by provider/model, ingestion job counts, and circuit-open gauges. Message finalize also checks the workspace daily cost budget (`QUOTA_FREE_DAILY_COST_USD` / `QUOTA_PRO_DAILY_COST_USD`); the first breach each day writes `audit_logs` (`budget.exceeded`) and optionally POSTs `BUDGET_WEBHOOK_URL`. Workflow/collaboration costs now enter the same daily budget because they write `usage_events`; each run checks the budget at terminal state. `/metrics` is unauthenticated (LAN assumption).
- **OpenAPI**: the app exposes `AI Power API` metadata, tag descriptions, and documented error responses (429/503 on message send, 413/415/503 on upload) at `/openapi.json` and `/docs`; `docs/api/quickstart.md` and `docs/api/errors.md` mirror the contract.
- **Health**: `/healthz` is liveness; `/readyz` checks `SELECT 1` and Redis `PING` and returns 503 with per-check status when a dependency is down.
- **File lifecycle**: deleting a document also removes its stored file; a daily worker cron deletes unreferenced files older than 24h. API and worker share the `uploads` compose volume.
- **Tests**: `tests/conftest.py` sets DB/JWT/upload/chunk env before importing the app, recreates the schema per test, and drives the ASGI app with `httpx.ASGITransport`. Conversation tests override `get_registry`; ingestion tests override `build_parser`/`build_embedder` via the `fake_ingestion` fixture. Coverage requires `concurrency = ["greenlet", "thread"]`.
- **External model services**: local Qwen `http://192.168.29.100:8083/v1` (llama.cpp), bge-m3 `http://192.168.29.100:8000/v1` (vLLM, 1024 dims), DeepSeek `https://api.deepseek.com`.

## Conventions

- Tests first: write the failing test, run it, then implement. Keep RED/GREEN evidence in `docs/tdd/`.
- Any new user-owned resource must filter by `user_id` and return 404 on cross-user access; add an isolation test with two users.
- Ingestion must be idempotent per `(user_id, kb_id, content_hash)`; every failure sets a typed `error_code` and `IngestionJob.status = failed`.
- Uploads: allowlist extensions (.pdf/.md/.txt), never trust the client filename or content type for paths; store as UUID + suffix under `UPLOAD_DIR`.
- SSE event contract is fixed: `meta`, `citation`, `delta`, `usage`, `done`, `error`; `error` is terminal, `citation` only appears for retrieved chunks actually used in the prompt.
- Never build citations by parsing model output; build them from `RetrievedChunk` IDs after `fit_context`.
- `usage_events` is append-only: never update or delete rows from business code; aggregate by query.
- Provider/embedding code must not import vendor SDKs outside `app/providers/`; keys come from settings/env only.
- Never log `Authorization`, provider API keys, or full document text.
- Windows-specific: use `.venv/Scripts/python.exe`; Docker host is `192.168.29.100`, not `localhost`; pass SQL to `psql` via stdin.
