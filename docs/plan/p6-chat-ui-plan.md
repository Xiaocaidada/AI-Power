# P6 Chat UI 重构规划

## 目标

把对话从“控制台中的一个表单页”改造成独立、完整的聊天工作区，交互参考 Claude / ChatGPT：

- 对话拥有独立布局与侧栏，不再与控制台全局导航挤在同一个 264px 侧栏里。
- 新建会话以“输入优先”：大号居中输入框是视觉主体，模型选择内嵌，项目 / Agent / 知识库 / 高级配置降级为 chip 与弹层。
- 会话页减少常驻技术噪音，消息操作按需出现。
- 保留平台差异化能力：引用、Agent 流程、trace、用量归属。

## 现状问题

1. `/chat` 在开口前平铺项目、Agent、模型、知识库、插件、提示词、变量、Agent 模式 8 个控件，输入框缩在最底部。
2. 控制台侧栏同时承担全局导航与会话历史，信息密度过高。
3. 会话 header 常驻 `provider · model · kb · prompt`；每条消息底部常驻模型、token、trace、复制、重新生成、反馈。
4. 缺少消息时间、按时间分组、智能滚动；附件入口只是 disabled 占位。

## 目标结构

```
┌──────────────────────┬──────────────────────────────────────────┐
│ 品牌 / 工作区切换     │ 标题（可编辑）       [模型] [设置] [⋯]     │
│ [ + 新对话 ]   ⌘K    │                                          │
│ [ 搜索会话… ]        │            消息区（max-w-3xl）            │
│ 置顶 / 项目 /        │                                          │
│ 今天 / 昨天 / 7 天 / 更早 │        用户气泡 →                    │
│                      │        助手全宽正文                       │
│                      │        [复制][重生成][反馈][引用][详情]   │
│ ──────────────────   │ ┌──────────── 输入区 ─────────────────┐   │
│ ← 返回控制台 主题/用户│ │ [📎] [模型▾]              [发送/停止] │   │
└──────────────────────┴──────────────────────────────────────────┘
```

### 新建会话页

- 居中标题与提示，大号 Composer（`max-w-3xl`）。
- 模型选择器位于 Composer 底部，按平台模型 / 我的模型分组。
- Composer 下方 chip：项目、Agent、知识库、高级设置。
- 高级设置弹层收纳：提示词模板与变量、插件、敏感插件确认、多 Agent 模式。
- 推荐提示词为 2×2 卡片。

### 会话页

- Header：可编辑标题、模型 chip（点击打开会话设置）、设置、更多菜单（导出 / 归档）。
- 用户消息：右对齐气泡，悬停显示时间与复制。
- 助手消息：全宽无气泡；操作条包含复制、重新生成、反馈、引用、运行详情。
- 运行详情折叠模型、provider、token、trace，避免常驻噪音。
- 智能滚动：用户停留在底部时才自动跟随；上翻历史不被打断。

### 侧栏

- 工作区切换、新对话、搜索（⌘K）。
- 顺序：置顶 → 项目筛选 → 今天 / 昨天 / 7 天内 / 更早。
- 悬停菜单：重命名、置顶、移动项目、归档；归档入口保留在底部链接。
- 底部：返回控制台、主题、语言、用户、退出。

本次实施切片 1–2。

## 决策

- 路由保持 `/chat`、`/chat/:id`，只替换外层布局，避免破坏深链与 E2E。
- 控制台侧栏移除会话历史；`/archive` 保留在控制台布局，聊天侧栏提供入口。
- 视觉采用 Claude 式极简：助手全宽、无头像、操作条低对比、强调正文。
- 模型 / 项目 / Agent / 知识库选择沿用现有创建会话请求体，不改变 API 契约。
- `usage_events` 与 SSE 事件契约不变。
